Data Preprocessing

Missing values, outliers, and unencoded categorical data are the three things most likely to break a model — or silently degrade it. This page covers all three, with a comparison table for each to help you choose the right method.

Multivariate Imputation

python
from sklearn.impute import KNNImputer
imputer = KNNImputer(n_neighbors=5)
df_imputed = imputer.fit_transform(df)

# MICE — models each missing feature iteratively from the others
from sklearn.experimental import enable_iterative_imputer
from sklearn.impute import IterativeImputer
imputer = IterativeImputer(max_iter=10, random_state=42)
df_imputed = imputer.fit_transform(df)

Group-Based Imputation

python
# First pass: mean by Neighborhood
df['LotFrontage'] = df.groupby('Neighborhood')['LotFrontage'].transform(lambda x: x.fillna(x.mean()))
# Fallback: global mean for anything still missing
df['LotFrontage'] = df['LotFrontage'].fillna(df['LotFrontage'].mean())
MethodWhen to use
Group-basedWhen rows share a meaningful category with mostly-complete data
Predictive (e.g. RandomForest)When the missing column relates to other features
MICEComplex inter-feature relationships
KNNNumeric data with meaningful distance
A simple rule of thumb

Always start with simple imputation to build a baseline. If missingness is under 5%, it's often good enough. Move to group-based, KNN, or MICE only if that baseline underperforms.

Outlier Handling

python
from scipy import stats
import numpy as np

def handle_outliers(df, column, method='zscore', threshold=3, action='report'):
    df_copy = df.copy()
    if method == 'zscore':
        z_scores = np.abs(stats.zscore(df_copy[column].dropna()))
        outlier_indices = df_copy[column].dropna().index[z_scores > threshold]
    elif method == 'iqr':
        Q1, Q3 = df_copy[column].quantile(0.25), df_copy[column].quantile(0.75)
        IQR = Q3 - Q1
        lower, upper = Q1 - threshold * IQR, Q3 + threshold * IQR
        outlier_indices = df_copy[(df_copy[column] < lower) | (df_copy[column] > upper)].index

    if action == 'remove':
        df_copy = df_copy.drop(outlier_indices)
    elif action == 'cap' and method == 'iqr':
        df_copy[column] = df_copy[column].clip(lower=lower, upper=upper)
    return df_copy

# Usage:
# df_clean = handle_outliers(df, 'SalePrice', method='iqr', threshold=1.5, action='cap')
Z-Score

When to use

Roughly normal data. Typically |z| > 3 flags an outlier.

IQR

When to use

More reliable for skewed data; also supports cap (winsorization).

Warning

Not every outlier is bad data — sometimes it's the exact signal you're looking for (e.g., fraud detection). Verify with domain knowledge before removing.

Categorical Encoding

python
from sklearn.preprocessing import LabelEncoder, OneHotEncoder, OrdinalEncoder

# Label Encoding — for ordinal or tree-based-model features
le = LabelEncoder()
df['encoded'] = le.fit_transform(df['category'])

# One-Hot Encoding — no ordering, sparse
ohe = OneHotEncoder(sparse_output=False, handle_unknown='ignore')
encoded = ohe.fit_transform(df[['category']])

# Target Encoding with smoothing — for high-cardinality features
global_mean = df['target'].mean()
stats_tbl = df.groupby('category')['target'].agg(['mean', 'count'])
smoothing = 1
stats_tbl['smoothed'] = (stats_tbl['mean'] * stats_tbl['count'] + global_mean * smoothing) / (stats_tbl['count'] + smoothing)
df['encoded'] = df['category'].map(stats_tbl['smoothed'])
MethodWhen to useWatch out for
LabelOrdinal categories, tree-based modelsImplies false order for linear models
One-HotFew categories, no orderDimensionality explosion
TargetHigh cardinality, related to targetData leakage without smoothing
FrequencyHigh cardinality, quick solutionMay not relate to target
Quick decision guide

Tree-based models (Random Forest, XGBoost) usually work fine with Label/Ordinal Encoding. Linear models and neural networks are safer with One-Hot, unless cardinality is high — then reach for Target or Frequency Encoding.
