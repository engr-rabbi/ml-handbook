FAQ Troubleshooting

Frequently Asked Questions

Conda environment vs. venv — which should I use?

Conda manages both packages and environments and can handle non-Python dependencies (CUDA, C libraries) — convenient for data science. venv is lighter, managing only Python packages. Conda is more common for ML/DL work.

One-Hot Encoding or Target Encoding — how do I decide?

With fewer than 10–15 categories, One-Hot is safe. For high-cardinality features, consider Target or Frequency Encoding — but apply smoothing and fit only on the training fold to avoid leakage. Details on the Data Preprocessing page.

GridSearchCV is taking too long — what should I do?

Shrink the parameter grid, switch to RandomizedSearchCV, or use Optuna for large spaces. Use n_jobs=-1 to leverage all CPU cores. See Hyperparameter Tuning.

SHAP vs. LIME — which should I pick?

For tree-based models, SHAP's TreeExplainer is fast and precise. For any black-box model needing a quick, simple local explanation, LIME works well. Details on the Explainable AI page.

Why does my model score well in training but poorly in production?

Usually data drift or data leakage. Monitor regularly (see MLOps) and always fit transformations only on the training fold via a Pipeline.

Best Practices

Always use a Pipeline

Keeps every transformation fit only on the training fold, preventing leakage.

Start simple

Build a baseline first, then add complexity step by step, measuring improvement each time.

Always cross-validate

Don't trust a single train-test split for your final performance estimate.

Fix your random state

Use a fixed seed for reproducibility across runs.

Version-control your environment

Commit environment.yaml or requirements.txt to Git.

Monitor in production

A model's job isn't over at deployment — track drift and retrain as needed.

Common Mistakes

Fitting transformations on the full dataset

Always fit() only on training data, then transform() both sets.

Shuffling time-series data before splitting

Leaks future information into training — see Time Series.

Looking only at accuracy on imbalanced data

Use precision, recall, F1, or ROC-AUC instead — see Model Evaluation.
