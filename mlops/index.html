Production & MLOps

MLOps: Versioning, Monitoring & Drift

A model's job isn't done at training — MLOps is the discipline of reliably persisting, tracking, and monitoring models once they're in the real world.

Model Persistence Drift Detection

Model Persistence

python
import joblib

joblib.dump(pipe, 'model.joblib')
loaded_pipe = joblib.load('model.joblib')
Pickle vs. Joblib

For large sklearn models packed with NumPy arrays, joblib is generally faster and more memory-efficient than pickle. Always ensure the same library versions when loading — a mismatch can cause silent errors.

Experiment Tracking

Tools like MLflow let you log parameters, metrics, and model artifacts for every training run — essential once you're iterating across dozens of experiments.

python
# pip install mlflow
import mlflow

with mlflow.start_run():
    mlflow.log_param("n_estimators", 200)
    mlflow.log_param("max_depth", 15)

    model.fit(X_train, y_train)
    rmse = evaluate(model, X_test, y_test)

    mlflow.log_metric("rmse", rmse)
    mlflow.sklearn.log_model(model, "model")

Data Drift Detection

After deployment, incoming data can gradually diverge from the training distribution — silently degrading performance.

python
def detect_drift(reference_df, current_df, threshold=0.05):
    drift_report = {}
    for col in reference_df.columns:
        if reference_df[col].dtype == 'object':
            ref_dist = reference_df[col].value_counts(normalize=True)
            cur_dist = current_df[col].value_counts(normalize=True)
            common = set(ref_dist.index) & set(cur_dist.index)
            diff = sum(abs(ref_dist[c] - cur_dist[c]) for c in common)
            if diff > threshold:
                drift_report[col] = f"Drift detected (diff: {diff:.3f})"
        else:
            rel_diff = abs(reference_df[col].mean() - current_df[col].mean()) / reference_df[col].mean()
            if rel_diff > threshold:
                drift_report[col] = "Mean drift"
    return drift_report
Production-grade alternative

For real systems, use a statistically rigorous approach — the Population Stability Index (PSI), a Kolmogorov–Smirnov test, or a dedicated library like Evidently AI — with automated reporting and alerting.

The MLOps Lifecycle

Version everything
Code, data, and model artifacts — not just code.
Automate retraining
Trigger retraining on a schedule or when drift is detected.
Monitor in production
Track prediction distributions, latency, and error rates.
Roll back safely
Keep previous model versions ready for instant rollback.

Once a model is monitored and versioned, the next step is serving it reliably — covered on the Deployment page.
