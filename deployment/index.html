Production & MLOps

Model Deployment

A trained model only creates value once it's actually serving predictions. This page covers wrapping a model in a REST API, containerizing it with Docker, and the tradeoffs between deployment options.

REST APIs Docker

Serving a Model with FastAPI

python
# pip install fastapi uvicorn
from fastapi import FastAPI
from pydantic import BaseModel
import joblib

app = FastAPI()
model = joblib.load("model.joblib")

class PredictionRequest(BaseModel):
    feature1: float
    feature2: float
    feature3: str

@app.post("/predict")
def predict(request: PredictionRequest):
    X = [[request.feature1, request.feature2, request.feature3]]
    prediction = model.predict(X)
    return {"prediction": float(prediction[0])}

# Run with: uvicorn main:app --reload

Containerizing with Docker

bash
# Dockerfile
FROM python:3.10-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
bash
docker build -t my-ml-api .
docker run -p 8000:8000 my-ml-api
Why containerize?

Docker packages your model, code, and every dependency into one reproducible unit — eliminating "works on my machine" issues when moving from development to production.

Cloud Deployment Options

AWS

SageMaker / Lambda

SageMaker for managed training+serving; Lambda for lightweight, event-driven inference.

GCP

Vertex AI

End-to-end managed ML platform with built-in monitoring and pipelines.

Azure

Azure ML

Managed endpoints with integrated MLOps tooling and model registries.

Start simple

For a first deployment, a Dockerized FastAPI app on a single cloud VM or a serverless function is often enough. Reach for a managed ML platform once you need built-in autoscaling, A/B testing, or team-wide model governance.
