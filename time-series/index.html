Classical ML

Time Series Analysis & Forecasting

Time-ordered data breaks the usual i.i.d. assumption behind most ML methods — order matters, and getting splitting and features wrong here is one of the most common sources of falsely optimistic results.

Correct Splitting Forecasting Models

Time Series Train-Test Splitting

python
# Never shuffle — split chronologically
train_size = int(0.8 * len(df))
train, test = df[:train_size], df[train_size:]

# For cross-validation, use a rolling/expanding window instead of random folds
from sklearn.model_selection import TimeSeriesSplit

tscv = TimeSeriesSplit(n_splits=5)
for train_idx, val_idx in tscv.split(df):
    X_train, X_val = X.iloc[train_idx], X.iloc[val_idx]
    y_train, y_val = y.iloc[train_idx], y.iloc[val_idx]
The #1 mistake

Randomly shuffling time-series data before splitting leaks future information into training — a scenario that's impossible in production and makes your validation score misleadingly good.

Time Series Feature Engineering

python
df['date'] = pd.to_datetime(df['date'])
df['year'] = df['date'].dt.year
df['month'] = df['date'].dt.month
df['dayofweek'] = df['date'].dt.dayofweek
df['is_weekend'] = (df['dayofweek'] >= 5).astype(int)

# Lag features — past values as predictors
df['sales_lag_1'] = df['sales'].shift(1)
df['sales_lag_7'] = df['sales'].shift(7)

# Rolling window statistics
df['sales_rolling_mean_7'] = df['sales'].shift(1).rolling(window=7).mean()
df['sales_rolling_std_7'] = df['sales'].shift(1).rolling(window=7).std()
Always shift before rolling

Notice the .shift(1) before .rolling() — without it, the rolling window would include the current row's own target value, leaking information the model wouldn't actually have at prediction time.

Classical Forecasting: ARIMA

python
from statsmodels.tsa.arima.model import ARIMA

# order=(p, d, q): p=autoregressive terms, d=differencing, q=moving-average terms
model = ARIMA(train['sales'], order=(2, 1, 2))
fitted = model.fit()

forecast = fitted.forecast(steps=30)
print(fitted.summary())

Modern Forecasting: Prophet

Facebook's Prophet is designed to be robust to missing data and handle seasonality/holidays with minimal tuning — a strong, fast baseline before reaching for deep learning.

python
# pip install prophet
from prophet import Prophet

# Prophet requires columns named exactly 'ds' (date) and 'y' (value)
prophet_df = df.rename(columns={'date': 'ds', 'sales': 'y'})

model = Prophet(yearly_seasonality=True, weekly_seasonality=True)
model.fit(prophet_df)

future = model.make_future_dataframe(periods=30)
forecast = model.predict(future)
model.plot(forecast)

Model Comparison

ApproachGood forHandles seasonality?
ARIMASingle series, short-to-medium horizonWith SARIMA extension
ProphetBusiness time series with strong seasonality/holidaysBuilt-in
Gradient Boosting with lag featuresMultiple related series, rich exogenous featuresVia engineered features
LSTM / Deep LearningLarge datasets, complex non-linear patternsVia architecture, needs more data
Start simple

A gradient-boosted model with well-engineered lag/rolling features is often a stronger, more practical baseline than a full deep-learning forecasting model — reserve LSTM-based approaches (see Deep Learning) for cases with abundant data and clearly non-linear temporal patterns.
